# Как команда работает с БД

## Ответственность
Руслан проектирует схему, пишет и проверяет миграции, seed, SQL, ограничения, индексы, права PostgreSQL и резервирование. Ануар и Ерасыл пишут бизнес-логику, API и интерфейсы, используют утверждённую схему и сообщают о новых требованиях. Олжас согласует сценарии и критерии.

**Схему изменяет только Руслан через миграции.** Разработчики не выполняют ручной ALTER TABLE и не меняют ORM-модели так, чтобы они расходились с миграциями. Изменение моделей согласовывается в PR Руслана. Начальный скелет создан помощником как исходная заготовка, а не как выполненная личная работа Руслана.

## Локальное окружение
Команды выполняются из корня репозитория после установки README. Активируйте `.venv`. Alembic настроен на database/migrations, модели — backend/app/models.py, единственный адрес — DATABASE_URL из .env.

```bash
source .venv/bin/activate
alembic current
alembic history
alembic upgrade head
PYTHONPATH=backend python database/seeds/demo_users.py
alembic check
```

Новая миграция, только Руслан:
```bash
git switch -c feature/db-course-schema
alembic revision --autogenerate -m "add courses modules and lessons"
```
Прочитать файл, проверить имена FK/UNIQUE/CHECK, nullable, backfill и downgrade. Ветки миграций не должны создавать несколько head без осознанного объединения. Применённые файлы не редактировать. Имена файлов — revision и короткое действие на английском; revision уникален, down_revision ссылается на предыдущую.

## Проверка на изолированной БД
Имя тестовой БД должно начинаться с mini_lms_test. Никогда не направляйте destructive команды на общую БД. Создайте её в локальном контейнере:
```bash
docker compose exec postgres createdb -U mini_lms mini_lms_test_local
export DATABASE_URL=postgresql+psycopg://mini_lms:local_demo_only@localhost:55432/mini_lms_test_local
alembic upgrade head
PYTHONPATH=backend python database/seeds/demo_users.py
PYTHONPATH=backend python database/seeds/demo_users.py
alembic check
RUN_DB_TESTS=1 PYTHONPATH=backend pytest backend/tests/test_database.py -q
alembic downgrade base
alembic upgrade head
alembic check
unset DATABASE_URL
```
Замените пароль/порт на свои значения. Если тестовая БД уже существует, повторять createdb не нужно. `downgrade base` удаляет все текущие предметные таблицы и данные! Только в одноразовой тестовой БД. После повторного upgrade seed требуется запустить снова.

Для проверки одной обратной миграции на такой БД: `alembic downgrade -1`. Обратные миграции с удалением полей нельзя считать безопасным способом обновления рабочего окружения. Для общего окружения — резервная копия, план forward-fix и согласование команды.

## Перед merge
Миграции применяются с нуля; seed запускается дважды без дублей; положительные и отрицательные проверки проходят; ORM совпадает с БД; документация обновлена. Руслан прикладывает результаты, другой участник проверяет. Нельзя записывать skipped как passed.

## Права и секреты
.env локален. Пароль PostgreSQL не передавать в frontend. Секреты, дампы и реальные данные не прикладывать к Issues. Локальные example.test — только демонстрационные записи. Роли приложения не заменяют права PostgreSQL.
